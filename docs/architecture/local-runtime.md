# Local runtime strategy

Local development comes first; this is not the production hosting design.

## Default Phase 1A dependencies

- PostgreSQL 18.7: one local cluster/container can host separate logical databases for tenant/service pairs. PostgreSQL's major-version-18 Docker volume target is `/var/lib/postgresql`.
- Redis 8.10.3: cache, rate limits and short-lived ephemeral state only; require authentication and tenant-aware keys. Never treat Redis as the source of truth.
- Mailpit 1.33.1: local SMTP capture for OTP and transactional-email development.

All host ports bind to `127.0.0.1`. Passwords are generated by `scripts/bootstrap_local.py`; `.env` and `infra/local/secrets/redis.conf` are Git-ignored. `docker compose up` starts only PostgreSQL, Redis and Mailpit.

## Optional and deferred dependencies

- RabbitMQ 4.4.0: optional `messaging` profile only when a service has an approved background-job consumer/retry use case.
- Kafka: deferred; not included in the default or current optional profile. Add only after an ADR justifies replayable/high-volume domain event streaming and operating cost. Kafka is not a generic replacement for task queues.
- Observability stack and object storage: add in later, bounded increments after instrumentation/media adapter requirements are approved.

## Operating principles

- Compose profiles start only required dependencies. Do not run every microservice locally by default.
- Use synthetic development data only.
- Service containers/processes use service-specific DB credentials, never bootstrap or provisioner credentials.
- Use persistent named volumes for local DB/cache data; `down -v` is destructive.
- Local filesystem media is a development adapter only; production media requires durable object storage.
- No cloud resources or public endpoints are created in the initial phases.
